# Playit agent management

Playit's web client uses its browser session for `POST /agents/list`, `POST /v1/tunnels/list`, and `POST /agents/delete`. The delete request includes `agent_id` and `tunnels_strategy`; the website supports `require_empty`, `delete_tunnels`, and `move_to_agent` with a null target to leave tunnels unassigned. KartLink implements those operations using its own persistent Playit browser partition. It does not send cookies to the renderer or request the user's password.

The agent key and website session have different scopes. The existing website session is reused, but signing in may be necessary even when room hosting already works. The list refreshes when the sign-in window closes. Account tunnel management uses `/v1/tunnels/list` and `/tunnels/delete`, with the existing agent key as a fallback when the website session is unavailable. The selected agent's tunnels are left unassigned by default; deleting its tunnels requires explicitly selecting that option. KartLink labels and protects only the agent and tunnel associated with its running processes, and clears its local connection when the user deletes its linked agent while idle.

Tests: `npm test` covers payloads, expired sessions, bad responses and deletion guards; `npm run test:integration` exercises the actual Electron IPC with an isolated fake account; `npm run test:ui` covers the management dialog and confirmation. The fake tests do not establish that a real website session is authenticated or that an actual account mutation succeeds. The Playit web API is undocumented for third-party use and could change.

On 2026-11-05, the installed 1.0.5 build successfully listed one tunnel via the saved hosting credential. A read-only account-wide `/agents/list` request using that hosting key returned `AuthRequired`; the website session was also unauthenticated on restart. A real authenticated account list and a real agent deletion are therefore still unverified. Do not store or print the key or cookie during diagnosis.

An isolated, in-memory disposable-session test attempted Playit's guest creation endpoint on 2026-11-05; Playit returned `NoLongerSupported`. No disposable agent was created. Consequently the real deletion check still requires an authenticated account and a deliberately selected disposable agent; the tests above do not mutate the user's account.
